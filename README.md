## 3. 학습 흐름 — 왜 이 순서로 배우는가

네 폴더는 따로 노는 주제가 아니라 **"AI 서비스 백엔드의 입력 처리 파이프라인"** 을 순서대로 쌓아 올립니다.

```
[01 Python 기초]   값을 다루는 법
      │           변수 · 조건문 · list/dict · 함수 · try-except
      ▼
[02 Class]         값과 동작을 하나로 묶는 법
      │           흩어진 함수 → 상태를 가진 서비스 객체
      ▼
[03 NumPy]         값을 대량으로, 빠르게 계산하는 법
      │           반복문 없이 배열 통째로 연산 (임베딩·벡터 연산의 토대)
      ▼
[04 Pydantic]      값이 "올바른지" 자동으로 보장하는 법
                  타입 힌트를 실제로 강제 → FastAPI 요청/응답 스키마로 직결
```

핵심 연결고리 하나만 기억하면 됩니다.

- `01`에서 배운 **타입 힌트(`name: str`)는 파이썬이 검사해 주지 않습니다.** 그냥 주석 수준입니다.
- `01~02`에서는 그래서 `if not cleaned: raise ValueError(...)` 같은 **검증 코드를 손으로** 짰습니다.
- `04` Pydantic은 바로 그 손수 짜던 검증을 **타입 힌트만 적으면 자동으로** 해 줍니다.

즉 `01 → 04`는 "검증을 수동으로 → 선언적으로" 옮겨가는 하나의 이야기입니다.

### 가상환경 (venv) 세팅

강의용 노트북(Windows)에는 이미 설치되어 있습니다. **다른 기기(macOS 등)에서 새로 받을 때** 아래를 따르세요.

**macOS / Linux**
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install numpy pydantic
```

**Windows (PowerShell)**
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install numpy pydantic
```

가상환경이 활성화되면 프롬프트 앞에 `(.venv)` 가 붙습니다. 빠져나올 때는 `deactivate`.

> `.venv/` 는 `.gitignore`에 등록되어 있어 **커밋되지 않습니다.** (기기마다 내용이 달라 공유하면 안 되는 폴더입니다.)
> 대신 아래 `requirements.txt` 로 "무엇을 깔아야 하는지"만 공유합니다.

### requirements.txt 로 환경 재현하기

```bash
# 현재 환경의 패키지 목록을 파일로 저장 (설치한 기기에서 1회)
pip freeze > requirements.txt

# 다른 기기에서 동일하게 복원
pip install -r requirements.txt
```

### 실행

```bash
# 프로젝트 루트에서, 가상환경을 활성화한 상태로
python 01_python-basic/day1_value_type.py
python 03_numpy/day3_numpy03.py
python 04_pydantic/day4_pydantic03.py
```

### 설치 확인

```bash
python -c "import numpy, pydantic; print(numpy.__version__, pydantic.VERSION)"
```

`ModuleNotFoundError`가 나면 가상환경이 활성화되지 않았거나, 에디터가 다른 파이썬 인터프리터를 보고 있는 경우입니다.
VS Code라면 `Cmd/Ctrl + Shift + P` → **Python: Select Interpreter** 에서 `.venv` 를 선택하세요.
